# 이상 탐지 모델 3종 벤치마크 보고서

PaDiM · PatchCore · EfficientAD 를 MVTec AD 의 hazelnut 카테고리에서 비교한 실험의 목적, 방법, 모델별 차이, 결과 정리.
작업 명세는 `anomaly_benchmark_spec.md`, 실패·우회 기록은 [ISSUES.md](ISSUES.md) 참고.

## 1. 무엇을 측정했나

### 1.1 목표 (명세 1장)

세 모델의 **정확도와 추론 속도의 상충 관계**를 같은 조건에서 측정한다. 확장 실험으로 같은 카테고리에서
**학습 이미지 수(100 / 200 / 300장)** 만 바꿔 성능 변화를 본다.

| 구분 | 내용 |
|---|---|
| 기본 과제 | 3모델의 정확도·추론 속도 비교 |
| 확장 실험 | 학습 장수 변화에 따른 성능 변화 (3모델 × 3장수 = 9회 실행) |
| 활용 | 저장된 체크포인트로 이미지 폴더를 정상/불량 판정 (`inspect_ckpt.py`) |

### 1.2 왜 이 비교인가

이상 탐지는 **정상 이미지만으로 학습**하고 "정상이 아닌 것"을 찾는다. 불량 샘플이 드물고 불량 종류를 미리 알 수 없는
상황을 가정한다. 이때 모델을 고를 기준은 정확도만이 아니다. 모델마다 다음 비용 구조가 다르다.

- 학습에 드는 시간과 방식 (통계만 계산하는가, 신경망을 실제로 학습하는가)
- 추론 한 장당 시간과 메모리
- 학습 데이터가 늘 때 그 비용이 어떻게 변하는가

그래서 한 가지 지표가 아니라 **정확도 · 추론 속도 · 학습 장수 민감도** 를 함께 측정했다.
(이 절은 명세의 목표와 모델 구조에서 정리한 설명이며, 별도의 사용 목적이 명세에 적혀 있지는 않다.)

### 1.3 측정 지표

| 지표 | 뜻 |
|---|---|
| Image AUROC | 이미지 한 장을 정상/불량으로 얼마나 잘 가르는가 (1.0 최고, 0.5 무작위) |
| Pixel AUROC | 불량 위치를 화소 단위로 얼마나 정확히 짚는가 |
| Image F1 | 임계값을 적용했을 때 정밀도·재현율의 조화평균 |
| 추론 시간 (ms/장), FPS | 배치 1, 워밍업 후, `cuda.synchronize` 적용, 이미지 로딩 제외. 전처리·모델·후처리 포함 |
| GPU 최대 메모리 (MB) | 추론 중 최대 할당량 |
| 학습 시간 (s) | `engine.fit` 소요 시간 |

## 2. 실험 설정

### 2.1 고정 조건 (명세 3장, 변경 금지)

| 항목 | 결정 | 이유 |
|---|---|---|
| 카테고리 | hazelnut 고정 | 원본 학습 이미지 391장이라 한 카테고리에서 100/200/300장이 모두 가능 |
| 장수 비교 | 카테고리는 두고 장수만 변경 | 카테고리를 바꾸면 장수 효과와 난이도 효과가 섞임 |
| 데이터 증강 | 사용 안 함 | 정상 분포가 바뀌어 장수 효과와 섞임 |
| test / ground_truth | 원본 그대로 (110장), 모든 실험 동일 | 평가 조건 고정 |
| 하이퍼파라미터 | test 성능을 보고 고르지 않음 | test셋 튜닝은 결과를 부풀림 |
| 입력 해상도 | 세 모델·학습·판정 모두 256×256 | 해상도가 다르면 비교와 체크포인트 판정이 어긋남 |

- test 110장 = 정상 40 + 결함 70 (crack 18, cut 17, hole 18, print 17).
- 학습 이미지 분할: 정렬한 391장을 시드 42로 한 번 섞어 앞 300/200/100장을 사용한다. 따라서 **100 ⊂ 200 ⊂ 300** 이다.
- 학습 시드는 42 하나뿐이다.

### 2.2 모델별 설정 (`common.py`)

| 모델 | 백본 | 설정 | 학습 반복 |
|---|---|---|---|
| PaDiM | resnet18 | layer1·2·3 특징 | 1 epoch (통계 계산) |
| PatchCore | wide_resnet50_2 | layer2·3, coreset 비율 0.1, 이웃 수 9 | 1 epoch (메모리 뱅크 구축) |
| EfficientAD | (자체 Student/Teacher) | model_size=small, 학습 배치 1 | **70,000 step** (논문 기준) |

anomalib 2.6.2 에서 실행했다. 세 모델은 모두 `Resize(256,256)` 만 쓰고 크롭은 하지 않는다.

## 3. 모델별 차이

### 3.1 한눈에 보기

| | PaDiM | PatchCore | EfficientAD |
|---|---|---|---|
| 핵심 아이디어 | 위치별 정상 특징을 가우시안으로 모델링 | 정상 패치를 메모리 뱅크에 저장하고 최근접 거리를 측정 | Student 가 Teacher 를 흉내 내도록 학습하고 차이를 측정 |
| 신경망 학습 | 없음 (평균·공분산 계산) | 없음 (패치 수집 + coreset) | **있음 (역전파, 70,000 step)** |
| 이상 점수 | 마할라노비스 거리의 최대값 | 메모리 뱅크까지의 최근접 이웃 거리의 최대값 (이웃 기반 재가중 적용) | Student-Teacher 차이 지도와 오토인코더-Student 차이 지도의 평균, 그 최대값 |
| 학습 시간 (이번 결과) | 19~33초 | 24~89초 | 약 3.3~5.4시간 |
| 추론 비용 | 작고 일정 | 메모리 뱅크가 클수록 증가 | 작고 일정 |

### 3.2 PaDiM

사전학습 CNN(여기서는 resnet18)의 여러 층에서 뽑은 특징을, **이미지 위치마다** 정상 이미지들의 분포(평균·공분산을 가진 가우시안)로
저장한다. 테스트 이미지의 같은 위치 특징이 그 분포에서 얼마나 떨어져 있는지(마할라노비스 거리)가 그 위치의 이상 정도다.

- 학습: 정상 이미지를 한 번 통과시켜 통계만 계산한다. 가중치를 갱신하지 않으므로 epoch 를 늘려도 결과가 같다.
  공분산에는 역행렬이 존재하도록 작은 정규화항(εI)을 더한다.
- 차원 축소: 여러 층의 특징을 이어 붙인 뒤 **무작위로 일부 차원만 골라** 줄인다(PCA 보다 효율적이라는 것이 논문 설명).
  anomalib 기본값은 resnet18 100차원, wide_resnet50_2 550차원이며, 이번 실험은 기본값을 썼다. 선택된 차원은 모델과 함께 저장된다.
- 이미지 이상 점수: 위치별 이상 맵(마할라노비스 거리)의 **최대값**.
- 추론: 논문이 "학습 데이터 크기와 무관한 낮은 시간·공간 복잡도"를 장점으로 든다. 이번 측정에서도 장수와 무관하게 일정했다.
- 위치별 공분산을 적은 이미지 수로 추정하면 불안정할 것이라는 것은 명세 9장의 **가설**이다(논문이 직접 다룬 내용은 아님).

### 3.3 PatchCore

사전학습 CNN(wide_resnet50_2)의 중간층(layer2·3) 특징을 **패치 단위**로 모아 메모리 뱅크를 만든다. 각 패치 특징은 주변 패치와
평균 풀링(anomalib 은 3×3)으로 섞어 지역 문맥을 담는다(논문의 local neighbourhood aggregation). 그대로 두면 양이 많아
**greedy coreset 샘플링**(k-center greedy, 서로 멀리 떨어진 대표 패치만 남김)으로 줄인다. 이번 설정은 10%이고 논문은 1%, 10%, 25%를 비교했다.
테스트 이미지의 각 패치에서 메모리 뱅크의 최근접 이웃 거리를 구하고, 그 최대값을 이미지의 이상 점수로 쓴다.
이웃 수(이번 설정 9)는 이 거리 자체를 평균 내는 데 쓰는 것이 아니라, 최대 패치 주변의 메모리 뱅크 이웃을 이용한 **재가중(reweighting)** 에 쓰인다.

- 학습: 역전파가 없다. 한 번 훑어 패치를 모으고 coreset 으로 줄인다. 논문이 "ImageNet 사전학습 네트워크를 대상 분포에 맞게 조정하지 않는다"고 설명한다.
- 추론: 패치마다 메모리 뱅크에서 최근접 이웃을 찾는다. **뱅크가 클수록 느리고 메모리를 더 쓴다.** 논문도 coreset 을 줄이면
  저장 공간과 추론 시간이 크게 줄어든다고 보고한다. coreset 비율이 고정이므로 뱅크 크기는 학습 장수에 비례하고, 이번 측정에서
  추론 시간과 GPU 메모리가 장수에 따라 늘어난 것과 맞는다.
- 이미지 한 장에서도 패치가 수백 개 들어가므로 소량 학습에도 강할 것이라는 것이 명세 9장의 가설이다.
  (논문은 학습 데이터의 일부만 써도 기존 최고 수준에 맞먹는다고 보고한다.)

### 3.4 EfficientAD

세 가지 네트워크로 구성된다.

- **Teacher**: 합성곱 4층짜리 얕은 패치 기술 네트워크(PDN). 큰 사전학습 네트워크(논문은 WideResNet-101)의 특징을 흉내 내도록
  **미리 증류해 둔 가중치**를 불러오며, 이번 학습에서는 **고정**이다(옵티마이저에 Student 와 오토인코더의 파라미터만 들어간다).
- **Student**: Teacher 와 같은 구조에 출력 채널을 두 배로 늘려, Teacher 출력과 오토인코더 출력을 동시에 예측한다.
- **오토인코더**: 정상 이미지에서 Teacher 의 특징을 복원하도록 학습된다(병목 64차원).

이상 맵은 두 가지를 평균(50:50)해서 만든다.

| 지도 | 계산 | 잘 잡는 이상 (논문 설명) |
|---|---|---|
| Student-Teacher | Student 의 첫 출력과 Teacher 출력의 제곱 차이 | 오염·얼룩처럼 **구조가 다른** 국소 이상 |
| 오토인코더-Student | 오토인코더 출력과 Student 의 두 번째 출력의 제곱 차이 | 위치·크기·배치가 어긋난 **논리적** 이상 |

각 지도는 검증 이미지의 분위수(0.9 와 0.995)로 정규화한 뒤 합치고, 이미지 이상 점수는 합친 지도의 **최대값**이다.
정상 이미지에서는 Student 가 Teacher 를 잘 따라 하므로 차이가 작고, 결함에서는 따라 하지 못해 차이가 커진다.
작은 네트워크 위주라 추론이 빠르도록 설계되었다(논문은 256×256 이미지에서 2.2 ms 의 지연 시간을 보고한다).

#### 왜 EfficientAD 만 실제로 학습했나

PaDiM 과 PatchCore 는 정상 이미지에서 **통계나 패치를 모으는 것**이 "학습"의 전부여서 신경망 가중치를 갱신하지 않는다.
EfficientAD 는 **Student 네트워크가 Teacher 를 흉내 내도록 실제로 역전파 학습** 해야 이상을 판별할 수 있다.
학습하지 않은 Student 는 정상 이미지조차 따라 하지 못하므로 차이가 의미가 없다. 그래서 이 모델만 반복 횟수를 정해 학습한다.

- **70,000 step**: 논문 기준 값을 따랐다. 이번 실행은 학습 배치가 1이라 1 step 이 이미지 1장이다.
  step 수를 고정했으므로 학습 이미지가 적을수록 같은 이미지를 더 많이 반복해서 본다
  (100장 약 700회, 200장 약 350회, 300장 약 233회). 명세 9장의 "장수가 적을수록 암기 위험" 가설과 연결된다.
- **ImageNet 이미지(anomalib 은 Imagenette)**: Student 가 정상 이미지 밖에서까지 Teacher 를 잘 따라 하게 되면 결함도 따라 해서
  이상이 안 잡힌다. 이를 막으려고 매 step 마다 정상 데이터와 무관한 ImageNet 이미지를 하나 넣고, 그 이미지에서 Student 출력의
  크기(L2)를 억제하는 **사전학습 벌칙항**이 논문 설계에 들어 있다. anomalib 은 이 보조 이미지로 ImageNet 의 10개 클래스 부분집합인
  Imagenette(약 1.5GB)를 자동으로 내려받아 쓴다. 이 벌칙항은 학습에만 필요하고 평가는 여전히 hazelnut test 로 한다.
- **Hard feature loss**: Student-Teacher 차이가 큰 상위 일부 값만 골라 역전파한다(anomalib 은 상위 0.1% 분위수 이상의 값).
  정상 이미지에서 점수가 튀는 값을 줄이기 위한 장치다.
- **추가 학습 비용**: 그래서 학습 시간이 PaDiM·PatchCore 보다 수백 배 길다(아래 결과 참고).

### 4.2 관찰된 것

- **정확도-속도 상충**: 빠른 순서(PaDiM → EfficientAD → PatchCore)와 정확한 순서(PatchCore → EfficientAD → PaDiM)가
  반대로 놓인다. PatchCore 추론은 PaDiM 의 약 2.5~3.5배 걸린다.
- **PatchCore**: Image AUROC 가 세 장수 모두 1.000 이다. 추론 시간(17.5 → 20.8 → 25.5 ms)과 GPU 메모리(476 → 716 MB)는
  학습 장수에 따라 증가한다. PaDiM·EfficientAD 는 장수와 무관하게 거의 일정하다.
- **EfficientAD**: Image AUROC 가 0.934 → 0.936 → 0.961 로 장수가 늘수록 올라가는 경향이다.
- **PaDiM**: Image AUROC 가 0.784 → 0.724 → 0.725 이며 100장일 때 가장 높다. Pixel AUROC(약 0.97)는 높은데
  Image AUROC 는 낮다. 이 차이의 원인은 확인하지 않았다.
- **학습 비용**: EfficientAD 학습은 약 3.3~5.4시간으로 PaDiM·PatchCore(수십 초~1.5분)와 비교가 되지 않는다.

### 4.3 명세 9장 가설과의 대조

| 가설 | 이 데이터에서 |
|---|---|
| PatchCore 가 장수 감소에 가장 완만하게 하락 | 하락이 없어 확인할 수 없음 (1.000 으로 천장) |
| PaDiM 은 소량에서 불안정 | 방향이 반대(100장이 최고). 원인 미확인 |
| EfficientAD 는 하락하고 편차 증가 | 장수가 줄면 하락하는 방향은 일치. 편차는 시드가 하나라 알 수 없음 |
| EfficientAD 가 가장 빠르고 PatchCore 가 느림 | PaDiM 이 가장 빠르고 EfficientAD 가 그다음. PatchCore 가 가장 느린 것은 일치 |

## 5. 한계와 해석 시 주의

- **시드 1개**: 100장과 200장 사이의 작은 차이(EfficientAD 0.934/0.936, PaDiM 0.724/0.725)는 시드가 바뀌면 순서가 바뀔 수 있다.
  그래프의 오차 막대는 편차가 0이라 의미가 없다. 시드 반복(명세 8장 7단계)은 하지 않았다.
- **쉬운 카테고리**: hazelnut 에서 PatchCore 가 1.000 에 도달해 장수 효과나 모델 간 정확도 차이가 이 지표로는 드러나지 않을 수 있다.
  다른 카테고리나 더 적은 장수는 명세 3장(변경 금지)에 따라 이번에는 다루지 않았다.
- **test 110장**: 한 장의 순위 변화에도 ROC 곡선이 계단처럼 움직인다.
- **속도 측정 조건**: GPU(RTX 3080), 배치 1, 이미지 로딩 제외. 다른 GPU·CPU 에서는 순서가 달라질 수 있다.
  이번에 잰 EfficientAD 는 약 10 ms 로 논문 보고값(2.2 ms)과 차이가 크다. 이번 측정은 전처리·후처리를 포함한 anomalib 구현 전체이고
  GPU 도 다르므로 논문 수치와 직접 비교할 수 없다. 이 문서의 속도는 같은 조건에서 잰 세 모델 사이의 상대 비교로만 쓴다.
- **학습 시간 편차**: EfficientAD 의 step 수는 같은데 학습 시간이 5.4 / 3.8 / 3.3시간으로 다르다. 같은 GPU 에서 다른 작업이
  함께 돌았을 가능성이 있으나 확인하지 않았다.
- **PaDiM 낮은 Image AUROC**: 문헌 보고값보다 낮아 보이나 원인을 조사하지 않았다. test 성능을 보고 설정을 바꾸지 않는다는
  명세 3장에 따라 그대로 두었다.
- **점수 비교 불가**: `pred_score` 는 모델별 정규화·임계값 기준이라 모델 간 점수 크기를 직접 비교하지 않는다.
  모델 비교는 이 문서의 지표로 한다.

## 6. 재현

`vison_ai2` 환경, `anomaly_benchmark/` 폴더에서 실행한다.

```bash
python split_dataset.py                          # 원본 복사 + 100/200/300 분할 (1회)
python benchmark.py --num-workers 0              # 3모델 x 3장수 (EfficientAD 때문에 8~10시간)
python benchmark.py --plot-only                  # 그래프만 다시 생성
python inspect_ckpt.py --model patchcore --count 300 --images dataset/hazelnut/test
```

| 파일 | 역할 |
|---|---|
| `common.py` | 경로·환경 변수·모델/Engine 팩토리·보조 함수 (학습과 판정이 공유) |
| `split_dataset.py` | 원본 복사, 시드 고정 분할 |
| `benchmark.py` | 학습·평가·속도 측정·CSV·그래프 |
| `inspect_ckpt.py` | 체크포인트로 이미지 폴더 판정 |
| `ISSUES.md` | 진행 중 실패와 우회 기록 |

데이터셋, 사전학습 모델, 체크포인트는 용량 때문에 저장소에 올리지 않았다.

## 7. 모델 설명 검증 기록 (2026-10-03)

3장의 모델 원리 설명을 논문 원문과 anomalib 2.6.2 소스로 대조했다.

| 확인 항목 | 논문 | anomalib 2.6.2 소스 | 결과 |
|---|---|---|---|
| PaDiM: 위치별 가우시안 + 마할라노비스, 이미지 점수 = 최대값 | 일치 | 모듈 설명 일치 | 문서 맞음 |
| PaDiM: 신경망 학습 없음, 추론이 학습 크기와 무관 | 일치 | - | 문서 맞음 |
| PaDiM: 무작위 차원 선택 | 있음 (PCA 보다 효율적) | `randperm` 으로 선택, resnet18 100 / wide_resnet50_2 550 | **문서에 없어서 추가** |
| PaDiM: "샘플 수가 적으면 공분산이 불안정" | 직접 언급 없음 | - | **명세의 가설로 표시** |
| PatchCore: 중간층 패치 특징 + 이웃 평균 풀링 | 일치 | `AvgPool2d(3,1,1)` | **풀링 단계 추가** |
| PatchCore: greedy coreset, 비율 1/10/25% 비교 | 일치 | k-center greedy, 기본 0.1 | 문서 맞음 (표현 보강) |
| PatchCore: 점수 = 최근접 거리의 최대값, 이웃은 재가중 | 일치 | 패치 점수는 1-NN, `num_neighbors` 는 재가중에 사용 | **이웃 수의 역할 수정** |
| PatchCore: 역전파 없음, 뱅크가 클수록 느림 | 일치 | - | 문서 맞음 |
| EfficientAD: Teacher = 증류된 얕은 PDN, 고정 | 일치 | PDN 을 eval 로 두고 사전학습 가중치 로드, 옵티마이저에는 Student·AE 만 | **Teacher 구조 설명 추가** |
| EfficientAD: 이상 맵 = Student-Teacher 와 AE-Student 의 평균, 점수 = 최대값 | 일치 | `0.5*map_st + 0.5*map_stae`, `amax` | **"AE 복원과의 차이" 표현 수정** |
| EfficientAD: 70,000 step, 배치 1, ImageNet 벌칙항 | 일치 | 벌칙 = Student 출력의 제곱 평균, 보조 이미지는 Imagenette | **ImageNet / Imagenette 구분 수정** |

### 참고: anomalib 설명문과 코드의 차이

anomalib 의 EfficientAD 모듈 설명문(`lightning_model.py`, `torch_model.py` 머리말)은 "사전학습 EfficientNet Teacher"라고 적혀 있다.
논문과 실제 코드는 Teacher 가 얕은 PDN 이다(코드는 `SmallPatchDescriptionNetwork` / `MediumPatchDescriptionNetwork` 를 쓰고
`pretrained_teacher_{size}.pth` 를 불러온다). 이 문서는 논문과 코드 기준으로 적었다.

### 출처와 검증 방법의 한계

- 논문: [PaDiM (arXiv 2011.08785)](https://arxiv.org/abs/2011.08785), [PatchCore (arXiv 2106.08265)](https://arxiv.org/abs/2106.08265),
  [EfficientAD (arXiv 2303.14535)](https://arxiv.org/abs/2303.14535)
- anomalib: 설치된 2.6.2 의 `models/image/{padim,patchcore,efficient_ad}` 소스와 모듈 설명문
- 논문 본문은 도구가 가져온 요약본(HTML 판)으로 읽었다. 논문 원문 PDF 를 직접 열어 확인한 것이 아니므로, 수치·세부 설정은
  인용 전에 원문으로 한 번 더 확인하는 것이 안전하다.
- anomalib 온라인 문서 페이지는 따로 열지 않았다. 문서 페이지의 원본인 소스의 설명문과 구현을 확인했다.
