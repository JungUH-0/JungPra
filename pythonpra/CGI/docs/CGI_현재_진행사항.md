## 2. 프로젝트 방향 (10-09 ~ 10-16 확정)

장기 흐름

1. 상의 옷 피팅
2. 퍼스널컬러 반영 — 피부톤 진단 + 옷 색 추천·변경
3. 관광지(한국 고궁 · 유럽 건축물)에 사람 합성
4. 그 합성 사진의 사람에게 배경에 맞는 옷(한복 · 유럽풍) 입히기

모델은 둘로 나누는 방향이다.

| 모델 | 역할 | 무엇으로 |
|---|---|---|
| A: 옷 → 사람 | 상의(나중에 전신) 입히기 | 옷 데이터로 미세조정한 AnyDoor. 학습 없이 옷 전용 모델(IDM-VTON · CatVTON 등)을 비교 기준으로 돌려 보는 안 |
| B: 사람 → 배경 | 고궁 · 유럽 건축물에 사람 넣기 | 원본 AnyDoor 공개 가중치 + CGIv2 후처리(되붙이기 · 그림자 · 얼굴 이식) |

- 같은 AnyDoor 를 옷 데이터로 학습하면 배경 합성 능력이 떨어질 수 있어 **원본 가중치는 따로 보관**한다.
- 10GB GPU 에서는 두 모델을 하나씩 올리고 내린다. 팀 합성은 최대 9.25GB 를 쓴다.
- 학습은 B200 까지 쓸 수 있다. 팀 환경(torch 2.5.1+cu121)도 B200(Blackwell, CUDA 12.8 이상 필요)에서는 그대로 돌지 않으므로 학습용 환경을 따로 맞춰야 한다.
- AnyDoor 원본 학습에 VITON-HD · FashionTryOn 이 이미 들어 있어, 같은 데이터로 다시 학습하면 새 정보보다 '옷 쪽 집중' 효과에 가깝다.
- 한복 · 유럽풍 옷은 전신 옷이고 지금 데이터에 없다 → 상의 피팅이 안정된 뒤의 선택 과제.

파이프라인 단계별 현재 구현

| 단계 | 팀 구현 (main) | 비고 |
|---|---|---|
| 1. 객체 추출 | SAM2.1 hiera **base+** · 점(포함·제외) + 박스. 점 1개일 때만 후보 3개 중 최고점 자동 선택, 여러 점·박스면 마스크 1개. 가장 큰 조각만 남기고 작은 구멍 채움. 화면 '다듬기'에서 브러시(추가)·지우개(삭제), 되돌리기 20번 | 입힐 자리도 인물 사진에 점 → SAM2 로 지금 입은 상의 → 다듬기. dev-cej: 포함 점이 찍힌 조각은 모두 남김 |
| 2. AnyDoor 합성 | `epoch=1-step=8687.ckpt` (16.8GB) · 50단계 · fp16 + save_memory + 가중치를 CPU 에서 열기 · 작업마다 무작위 seed 를 만들어 기록 · 선택: shape_control(칠한 모양 그대로) · refine(옷 경계 다듬기, iseg) · 대기열 한 장씩 · 서버 켤 때 예열 | RTX 3080 에서 1건 약 60초 · 최대 9.25GB. AnyDoor 원본 파일은 고치지 않고 읽어서 메모리 안에서만 바꿔 실행. dev-cej: 크롭 1.3배 고정 (원본은 무작위) |
| 3. 후처리 | main 에는 없음. dev-cej `restore.py`: 입힐 자리 윗경계 위 = 원본, 아래 = 합성 결과, SAM2 로 찾은 새 상의는 경계 위라도 유지, 경계 20px 섞기 | 팀 기록: 100건에서 얼굴 차이(MAE) 5.81 → 0.36, 어깨 끝 잘림 59 → 0건. 윗경계 **아래**(팔 · 손 · 하의 · 옆 배경)는 생성 결과 그대로 |

API (팀 명세 `docs/api.md`): `POST /api/extract` (image_id · points · box) → `POST /api/compose` (extraction_id · person_image_id · area_mask · garment_mask · refine · shape_control) → `GET /api/jobs/{job_id}` → 결과 · 사진첩. 명세 8장 미정: box · garment_mask 채택 여부 등.

## 4. 후처리 계획 (팀 저장소 기준)

| 종류 | 무엇 | 언제 | 완료 기준 |
|---|---|---|---|
| 모델과 상관없는 것 | dev-cej `restore.py` 를 바탕으로, 윗경계 아래에서도 **옷 영역 밖은 원본**으로 되돌리기 | 1주차 | 옷 영역 밖 화소 = 원본 (얼굴 · 팔 · 손 · 하의 · 배경) |
| 측정 | 원본 옷과 결과 옷의 색 차이 (LAB ΔE) | 1주차에 학습 전 값, 4주차에 학습 후 값 | 같은 방법 · 같은 입력으로 두 번 |
| 모델에 따라 달라지는 것 | 색 보정 · 경계 다듬기 · 무늬 보존 중 꼭 필요한 한두 개 | 4주차 (학습 뒤) | 측정 수치로 필요하다고 나온 것만 |

- `restore.py` 는 EJAE(AI 기능 · 서버 담당)가 dev-cej 에서 작업 중이다 → 같은 파일을 고치기 전에 먼저 맞춘다.
- 색 보정은 일반 색 맞춤(주변 장면에 맞춤)이 아니라 **원본 옷 색 쪽**으로 맞춘다. 퍼스널컬러에서는 주변에 맞추면 오히려 해롭다.
- 예상되는 어려운 점: 새 옷이 원래 옷보다 짧거나 작으면 원래 옷 영역 중 덮이지 않은 곳이 남는다 — 처리 규칙을 정해야 한다.
- 배경 합성(모델 B)용 후처리는 CGIv2 것을 가져와 쓴다.
