## 1. 새 대화가 먼저 알아야 할 현재 상태 (10-06 기준 — 0절 먼저)

- 프로젝트는 **내부 테스트용 이미지 합성**이다. 공개 서비스 출시는 현재 목표가 아니다.
- **1안:** 사용자 자신의 사진을 국내외 명소에 넣는다. 얼굴 정체성과 원본 배경 보존이 중요하다.
- **2안:** 사람 배경에 **시계·가방·자동차**를 합성한다. 자동차는 타고 내리는 장면이 아니라 사람 옆·앞에 배치한다.
- 객체와 배치 위치는 사용자가 선택하는 흐름이 기본 의도다. 자동 배치는 보조 기능으로 구현됐으며 사용자 선택을 대체해야 하는 필수 조건으로 취급하지 않는다. 시계는 손목 착용, 가방은 들거나 메는 구도를 목표로 한다.
- 반지·목걸이는 제외했다. 퍼스널컬러는 미착수 예비안이고, 영상/VACE는 보류다.
- 기존 AnyDoor 사전학습 가중치를 기준선으로 사용한다. CGIv2는 전처리·후처리·배치·평가를 별도 구현한 코드다.
- **CGIv2는 인물 되붙이기·접지 그림자·2안 초기 테스트까지 진행됐다.** 예전 요약의 미완료 표시는 뒤의 기록으로 갱신해야 한다.
- **CGItest는 별도 Gradio 프로그램이다.** 현재 `app.py`는 자체 `AnyDoor/run_inference.py`를 호출한다. CGIv2 기능이 연결된 웹 앱으로 취급하면 안 된다.
- T4 학습은 실행 경로 확인에 성공했지만, 목표 데이터로 품질을 개선한 새 가중치를 저장·검증한 상태는 아니다.
- LoRA와 부분 파인튜닝이 논의됐으나 최종 학습 방식은 미결정이다. 이번 요청은 대화 정리이며 학습 시작 요청이 아니다.

현재 코드에서 읽은 두 경로:

```text
CGIv2
  CGI venv: 배치/마스크 분석
    → AnyDoor venv: 확산 생성
    → CGI venv: 얼굴 이식/되붙이기/그림자/평가
```

`CGItest/start.bat`은 `CGI/AnyDoor/.venv`의 Python을 사용한다. 따라서 **코드 사본과 실행 가상환경 위치도 다르다.** 파일·가중치 중복 제거 또는 두 프로그램 통합은 별도 구현 작업이며 이번 정리에 포함하지 않았다.

## 4. 결정이 바뀐 흐름

1. CGI v1에서 마스크·매팅·경계 문제를 개선했다.
2. VACE를 설치·검토했지만 느린 실행 원인을 해결하지 못했고 영상은 현재 범위에서 제외했다.
3. CGI v1 일부를 바꾸는 방향 대신 AnyDoor 기반으로 구성하기로 했다.
4. AnyDoor를 원본으로 복구한 시점이 있었으나, 이후 로컬 실행을 위해 10GB 패치를 다시 적용하고 유지하기로 했다.
5. CGIv2에서 기존 가중치를 유지하며 배치·얼굴·배경 보존·그림자를 개선했다.
6. 2안은 최종적으로 시계·가방·자동차로 좁혔다. 자동차 탑승·하차와 반지·목걸이는 현재 범위가 아니다.
7. 학습 계산을 이해하는 T4 확인용 실행과 실제 성능 개선용 학습을 구분했다.
8. 추가 학습을 통해 별도 가중치나 어댑터를 만들 가능성은 열어 두었다. **기준 가중치 보존과 향후 파인튜닝은 양립한다.**

### 수치 해석 주의

### 보존할 로컬 패치 요약

`CGI/_anydoor_backup/anydoor_10gb_fixes.patch`와 `docs/anydoor_local_10gb.md`에 상세 내용이 있다. 패치를 재적용하지 않고 설명만 통합했다.

## 13. 이후 작업 규칙

이전 사용자 지시와 CGIv2 인계 기록에서 보존한 규칙이다. 사용자의 후속 명시적 지시가 있으면 그 범위와 충돌 여부를 먼저 확인한다.

1. 학습·실험을 임의 실행하지 않는다. 작성·수정과 실제 실행을 구분한다. 과거 특정 테스트 승인을 새 실험 전체의 승인으로 확대하지 않는다.
2. 가상환경 생성·패키지 설치는 기본적으로 명령어만 제공한다.
3. 시간이 드는 실행 전에는 목적과 예상 작업을 알린다. GPU 작업을 동시에 돌리지 않는다.
4. CGIv2 코드/설정 변경은 이유·도구·값·검증 결과를 CHANGELOG에 기록한다.
5. CGIv2 기능은 AnyDoor 외부에서 구현하고 기존 로컬 실행 패치는 보존한다.
6. torch 업그레이드·torch.load 보안 검사 우회를 임의 수행하지 않는다.
7. 기존 HANDOFF의 다운로드 규칙: 파일명·출처·크기를 제시하고 사용자의 다운로드 승인 범위를 확인한다.
8. 기존 입력·마스크·raw·결과·설정·보고서를 덮어쓰거나 지우지 않는다. 비교는 같은 파일을 사용했는지 먼저 확인한다.
9. 구현됨/실행됨/품질 개선됨/일반화됨을 구분한다. 코드 존재나 점수 상승만으로 전체 성공을 선언하지 않는다.
10. 문서·스냅샷은 과거 상태의 근거다. 실제 변경을 시작하기 전 현재 파일과 다시 대조한다.
11. 후속 비교는 객체 2장 × 배경 2장을 기본으로, 생성 파라미터를 고정하고 도구를 바꾸는 의도를 유지한다. 새 명시적 요청이 없는 한 임의 격자 탐색으로 바꾸지 않는다.
12. 개념을 먼저 설명한 뒤 같은 용어로 코드와 연결한다. 사용자가 질문에 먼저 답하라고 하면 구현보다 답변을 먼저 한다. 다른 채팅이 같은 파일을 수정 중인지 작업 전에 확인한다.
