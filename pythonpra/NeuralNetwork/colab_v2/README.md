# Food-11 실험 v2 — 설계

v1(30개 조합)에서 받은 지적을 설계 단계에서 막는 것이 목적이다.
결과를 더 높이는 게 아니라 **주장할 수 있는 결과**를 만드는 것이 목표.

---

## v1이 무너진 네 지점

| # | 지적 | v2의 차단 방법 |
|---|---|---|
| 1 | 두 CNN이 다른 모델이었다 (파라미터 11.3배) | 설정 하나에서 두 모델을 만들고, **파라미터 수가 다르면 실행 거부** |
| 2 | 한 단계에서 변수를 여러 개 바꿨다 | 기준 조건에서 **한 축씩만** 이동. 조건은 코드가 아니라 설정값 |
| 3 | 시드 미고정 + 대부분 1회 실행 | 시드 `[0,1,2]`를 명시적으로 반복. 보고는 **평균 ± 범위** |
| 4 | 학습률을 통제 변수로 썼다 | 학습률을 **연구 질문으로 승격** (Phase 1) |

가장 큰 전환은 4번이다. "왜 1e-3으로 통일했나"라는 질문 자체가 사라진다.

---

## 설계 원칙

### 원칙 1 — 설정 하나, 모델 둘

```
Config(dataclass)  ──┬──> build_keras(cfg)
                     └──> build_torch(cfg)
```

두 함수는 같은 `cfg`를 읽는다. 조건을 바꾸려면 `cfg`를 바꾸는 수밖에 없고,
한쪽만 고치는 실수가 구조적으로 불가능하다.

### 원칙 2 — 기본값에 기대지 않는다

`Config`는 **모든 값을 명시**한다. 패딩, 풀링 크기, 은닉층 수, 증강 강도까지.
v1에서 "고정한 조건"과 "그냥 기본값을 쓴 것"이 섞였던 게 설계 지적의 뿌리였다.

증강 강도는 **도(degree) 단위 하나로** 정의하고 각 어댑터가 변환한다.
v1에서 `RandomRotation(0.1)`=±36°와 `RandomRotation(10)`=±10°가 어긋났던 사고 방지.

### 원칙 3 — 실행 전에 검사한다

```python
assert_param_match(cfg)   # 파라미터 수가 다르면 예외
```

이 줄을 통과하지 못하면 실험이 시작되지 않는다.

### 원칙 4 — 결과는 즉시 디스크에

`results.csv`에 한 줄씩 append. 런타임이 끊겨도 앞선 실행이 남는다.
v1에서 GPU 할당 소진으로 실행 하나를 통째로 잃은 적이 있다.

---

## 실행 계획

`SEEDS = [0, 1, 2]`

### Phase 1 — 학습률 탐색 · 12회
> **옵티마이저마다 적정 학습률이 다른가?**

```
{sgd, sgd_momentum, adam} × {1e-4, 3e-4, 1e-3, 1e-2}
5 epoch · 시드 0만 · 짧게
```

여기서 각 옵티마이저의 최적 lr을 정한다. Phase 2의 입력이 된다.
**v1에서 가장 크게 지적받은 부분이 여기서 결과로 바뀐다.**

### Phase 2 — 옵티마이저 비교 · 9회
> **각자 최적 lr에서 비교하면 차이가 남는가?**

```
{sgd, sgd_momentum, adam} × 시드 3개
각자 Phase 1의 최적 lr · 30 epoch · EarlyStop
```

"공정한 비교"는 같은 lr이 아니라 **각자 최선에서 붙이는 것**이다.

### Phase 3 — 정규화 축 분해 · 15회
> **정규화 기법들은 대체되는가, 누적되는가?**

기준 조건에서 한 축씩 끄고 켠다:

```
증강 · Dropout · SpatialDropout · BatchNorm · weight decay
5축 × 시드 3개
```

v1의 결론 ②가 Dropout과 파라미터 수가 섞여 흔들렸다. 여기선 한 축씩 떼므로
각각의 기여를 분리해서 잰다. SpatialDropout은 v1에 없던 축이다.

### Phase 4 — 프레임워크 · 6회
> **조건을 완전히 맞추면 프레임워크가 영향을 주는가?**

```
동일 cfg × {keras, torch} × 시드 3개
```

원칙 3의 파라미터 검사를 통과한 뒤라야 이 질문에 답할 자격이 생긴다.

**합계 42회** (v1은 36회)

## 기록 항목

`results.csv` 한 행이 실행 하나. v1은 정확도만 봤고, 그게 한계로 남았다.

| 열 | 내용 |
|---|---|
| `phase, cfg_id, framework, seed` | 식별 |
| 모든 `Config` 필드 | 조건 전체 (재현용) |
| `n_params` | 파라미터 수 (일치 확인용) |
| `epochs_ran, stopped_by` | 실제 학습 길이, 종료 사유 |
| `train_acc, val_acc, test_acc` | 정확도 |
| `train_loss, val_loss, test_loss` | 손실 |
| **`per_class_recall`** | 클래스별 재현율 — v1에 없던 것 |
| **`lr_history`** | 학습률 변화 — ReduceLR 발동 여부가 여기 남는다 |
| `wall_sec` | 실행 시간 |

`per_class_recall`과 `lr_history`가 v1의 미확인 항목 둘을 직접 메운다.

## 미탐색으로 남기는 것

처음부터 선언한다. "고정했다"가 아니라 **"안 해봤다"**로 적는다.

- 이미지 해상도 (128 고정)
- 배치 크기 (32 고정)
- Conv 블록 개수 (3 고정)
- 커널 크기 (3 고정)
- 시드 3개는 적다 — 5~10이 이상적
- Phase 1이 5 epoch 단축 탐색 — 긴 학습에서 최적 lr이 달라질 수 있음
