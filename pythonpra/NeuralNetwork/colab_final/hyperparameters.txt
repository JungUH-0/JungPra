================================================================
프레임워크 간 조건 불일치 (해석 시 주의)
================================================================

1. Dropout 유무
     Keras   Flatten 뒤 Dropout(0.5) 있음
     PyTorch 3개 파일 모두 Dropout 없음
   -> 정규화 총량이 달라, AdamW의 weight decay 효과가
      두 프레임워크에서 정반대로 나타난 원인으로 추정됨

2. 분류 헤드 구조
     Keras   Flatten -> Dropout -> Dense(11)
     PyTorch Flatten -> Linear(128) -> ReLU -> Linear(11)
   -> PyTorch 쪽에 은닉 Dense층이 하나 더 있음

3. 증강 종류
     Keras   Flip + Rotation + Zoom   (3종)
     PyTorch Flip + Rotation          (2종, Zoom 없음)

4. 회전 강도 (같은 이름, 다른 단위)
     Keras   RandomRotation(0.1)  -> 2pi의 비율,  약 ±36도
     PyTorch RandomRotation(10)   -> 각도 직접,     ±10도

5. EarlyStopping patience
     keras2 = 3   /   torch2 = 5
   -> torch2는 BatchNorm 통계 안정화를 기다리려 5로 늘린 것

6. keras1 vs torch1 옵티마이저
     keras1 = Adam   /   torch1 = SGD + momentum 0.9
   -> 이 둘은 직접 비교 대상이 아님

7. 학습률 1e-3 고정
     Adam 계열에는 기본값이지만 SGD에는 평소의 1/10
   -> torch1의 SGD가 불리한 조건이었을 가능성

2. 학습 곡선 그래프 추가 (6개 전부)
     - epoch별 train/validation 정확도와 손실을 2패널로 출력
     - 상단 중앙에 모델명 + 옵티마이저, 그 아래 설정값 표기
     - curve_keras1.png ~ curve_torch3.png 로 저장 (170dpi)
     - Colab에서 자동 다운로드 시도

3. PyTorch train() 함수 수정 (torch1~3)
     기존에는 배치 loss만 출력하고 반환값이 없어서
     train 곡선을 그릴 수 없었음.
     epoch 단위 평균 loss와 정확도를 반환하도록 변경.
     test()도 (loss, accuracy) 두 값을 반환하도록 통일.

4. torch2의 중복 정의 정리
     loss_fn과 optimizer가 각각 두 번 정의돼 있던 것을 한 번으로.

주의 - 위 1~7번 불일치는 의도적으로 그대로 두었음
================================================================
이미 기록된 실험 결과와 어긋나면 안 되므로 구조/증강/patience는
건드리지 않았다. 발표에서는 "한계" 항목으로 밝히는 것이 맞다.

만약 완전히 공정한 재비교를 원한다면 다음을 맞춰야 한다:
  - PyTorch에 Dropout(0.5) 추가, 은닉 Dense층 제거
  - PyTorch 증강에 Zoom 추가, 회전 강도를 ±36도로 통일
  - patience를 양쪽 동일하게
  - SGD는 lr=1e-2로 별도 실험
