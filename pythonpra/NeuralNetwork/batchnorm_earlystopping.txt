================================================================
BatchNorm과 EarlyStopping의 충돌
Food-11 실험 중 PyTorch CNN에서 겪은 문제 정리
================================================================


[1] 근본 원인 - BatchNorm은 학습 때와 평가 때 다른 계산을 한다
----------------------------------------------------------------

  model.train()  →  지금 배치 32장의 평균/분산으로 정규화
  model.eval()   →  학습하며 누적해온 running mean/var로 정규화

평가할 때는 이미지가 한 장씩 들어올 수도 있어서 "배치 평균"이라는 게
의미가 없다. 그래서 학습 내내 통계를 따로 축적해둔다.

문제는 이 축적이 느리다는 것:

  running_mean = (1 - momentum) x running_mean + momentum x 배치평균

PyTorch 기본값 momentum=0.1 이면 배치 하나당 10%씩만 이동한다.
게다가 초기값이 running_mean=0, running_var=1 이라서
실제 활성값 분포와 무관한 값에서 출발한다.


[2] 그래서 초반 val 성능은 실제 실력보다 나쁘게 나온다
----------------------------------------------------------------

학습 초반에는 가중치가 빠르게 변하니 활성값 분포도 계속 움직인다.
러닝 통계는 그 움직이는 과녁을 10%씩 쫓아가는 셈이라 계속 뒤처진다.

  => 초반 몇 epoch의 val_loss는 "모델이 얼마나 나쁜가"가 아니라
     "BatchNorm 통계가 얼마나 덜 여물었나"를 상당 부분 반영한다.

Conv 블록이 3개면 BatchNorm도 3개가 쌓여 있다.
1층 통계가 어긋나면 2층에 들어가는 분포가 틀어지고, 그게 3층으로
전파되기 때문에 깊을수록 안정화가 더 오래 걸린다.


[3] EarlyStopping이 이것을 오해한다
----------------------------------------------------------------

EarlyStopping은 val_loss가 개선되지 않은 epoch을 세다가
patience에 도달하면 학습을 멈춘다.

그런데 위 이유로 초반 val_loss가 출렁이면, 학습이 멈춘 게 아니라
노이즈 때문에 3연속 "개선 실패"가 쉽게 만들어진다.
patience=3은 이 구간을 버티기엔 너무 짧다.

실제 우리 로그:

  Epoch 7: Accuracy 34.3%, loss 1.8989
  Epoch 8: Accuracy 34.3%, loss 1.9770   <- 정확도 그대로, loss만 출렁
  Early stopping at epoch 8              <- 8 epoch 만에 종료, test 36.5%

patience를 5로 늘리고 재실행 -> 12 epoch까지 진행, test 54.5%


[4] 주의 - 우리 케이스는 원인 특정이 안 된다 (정직하게 밝힐 부분)
----------------------------------------------------------------

재실행할 때 두 가지를 동시에 바꿨다:
  - patience 3 -> 5
  - BatchNorm <-> ReLU 순서

그래서 36.5% -> 54.5% 개선분이 어느 쪽 덕인지 분리할 수 없다.

게다가 Keras는 patience=3으로도 멀쩡히 17 epoch까지 진행됐다.

  => "BatchNorm이 있으면 항상 조기 종료된다"가 아니라,
     "초반 val 지표가 불안정해질 여지가 생기고,
      그때 짧은 patience가 취약해진다" 정도로 말하는 것이 정확하다.


[5] 덤 - 두 프레임워크의 momentum이 정반대다
----------------------------------------------------------------

  PyTorch  nn.BatchNorm2d          기본 momentum=0.1   -> 배치마다 10% 갱신
  Keras    BatchNormalization      기본 momentum=0.99  -> 배치마다  1% 갱신

같은 이름의 파라미터가 반대로 동작한다.
  - PyTorch: "새 값을 얼마나 반영할지"
  - Keras  : "옛 값을 얼마나 유지할지"

그래서 momentum=0.9를 두 프레임워크에 똑같이 넣으면
완전히 다른 동작이 된다.
(He 초기화 기본값 차이와 같은 종류의 함정)


[6] 실무 대응
----------------------------------------------------------------

  1. BatchNorm을 쓰면 patience를 넉넉히 잡는다 (3보다는 5~10)

  2. 최소 학습 epoch을 강제한다
     "10 epoch 전에는 절대 멈추지 않는다"

  3. val_loss 대신 val_accuracy를 모니터링한다
     정확도가 loss보다 덜 출렁이는 경우가 많다

  4. Dropout은 이 문제가 없다
     평가 때 그냥 꺼지면 끝이라 누적 상태가 없기 때문.
     BatchNorm만 "학습되는 통계"를 갖고 있다.
