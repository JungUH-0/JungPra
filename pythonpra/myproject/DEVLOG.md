# 개발 기록 (요구사항 · 결정 · 근거)

이 프로젝트를 만들면서 **무엇을 요구했고, 왜 그렇게 결정했는지**를 남긴 문서.
특히 **한 번 만들었다가 되돌린 것들**이 많은데, 그 이유를 적어두지 않으면
나중에 같은 시도를 반복하게 되므로 실패한 시도와 그 원인도 함께 기록한다.

---

## 1. 로컬 LLM 도입

**요구**: 제스처에 사용자가 원하는 명령을 직접 넣을 수 있게 하고 싶다.

**결정**
- Ollama + `qwen2.5:3b-instruct` (로컬 실행)
- LLM은 **제스처 인식이 아니라 "명령 해석"** 만 담당

**근거**: 제스처 인식은 20~40fps로 돌아가는 실시간 수치 분류 문제라 LLM에 맞지 않는다.
반대로 "이 문장이 어떤 동작을 뜻하는가"는 LLM이 잘하는 일이다. 그래서 역할을
**인식(실시간) → 이름 → LLM 해석(비실시간) → 실행**으로 나눴다.

**중요한 성질**: LLM은 아무것도 "학습"하지 않는다. 매번 `SYSTEM_PROMPT`(지시문 + 예시)를
명령문과 함께 통째로 보내고, 모델은 그 자리에서 읽고 따를 뿐이다. 그래서 규칙을
영구히 바꾸려면 대화로 알려주는 게 아니라 **`SYSTEM_PROMPT` 텍스트 자체를 고쳐야 한다.**

## 2. 손동작 — 마우스 제어

### 커서 기준점: 검지 끝 → 손바닥 중심

**문제**: 검지 끝을 커서로 쓰니, 클릭하려고 엄지-검지를 붙이는 **마지막 순간에
검지가 움직여서** 커서가 목표에서 벗어난 채로 클릭됐다.

**해결**: 커서 기준점을 **손바닥 중심(손목 + 4개 MCP 관절 평균)** 으로 변경.
손바닥은 핀치 동작에 거의 영향을 받지 않아 클릭 순간에도 위치가 안정적이다.

### 감도

화면 전체를 그대로 매핑하면 손을 크게 움직여야 해서, 프레임 중앙 일부만 화면
전체에 매핑하는 방식으로 증폭. `0.2(1.67배) → 0.08(1.19배) → 0.15(1.43배)` 로 조정.

> **감도와 반응속도는 별개다.** 감도는 `CURSOR_ACTIVE_MARGIN`(증폭), 반응속도는
> `CURSOR_SMOOTHING`(떨림 보정 지연)이 담당한다. "정교하지만 느리지 않게"는
> 증폭만 낮추고 스무딩은 그대로 두면 된다.

### 우클릭: 검지+중지 겹치기 → 엄지를 손바닥 중앙으로

**문제**: 손날 자세를 취하면 손가락들이 자연스럽게 붙어서 검지+중지 조건이 같이
만족돼 우클릭이 오발동했다.

**해결**: 손날 자세와 무관한 동작인 "엄지를 손바닥 중앙으로 넣기"로 교체.

### 휠 스크롤: 중지 단독 → 약지+새끼 + 손 전체 이동

**시도 1**: 중지만 펴고 그 끝을 위아래로 → **실패**. 약지는 인대 구조상 중지·새끼와
같이 움직여서, 중지를 펴는 순간 약지도 펴지며 자세 조건이 깨졌다.

**시도 2**: 고정 좌표 거리로 활성화 판정 → **실패**. 카메라와의 거리에 따라 정규화
좌표에서의 거리가 달라져서 값을 못 맞췄다 (가까우면 너무 쉽고 멀면 불가능).

**해결**: 손가락 하나의 미세 동작 대신, **이미 검증된 "손 전체를 위아래로 움직이기"**
방식을 재사용. 약지+새끼만 말면 되므로 손 자세도 편하다.

### 예/아니오: 엄지척 / 엄지다운

**문제**: 엄지다운을 하려고 손을 움직이는 도중 **잠깐 엄지업처럼 보이는 전환 자세**를
거치면서 "예"가 먼저 발동했다.

**해결**: 같은 상태를 **1초 이상 유지**해야 확정.

## 3. 손 방향(손바닥/손등/손날) 판정

이 판정 하나에서 여러 번 문제가 나왔고, 원인이 전부 달랐다.

| 문제 | 원인 | 해결 |
|---|---|---|
| 손이 멀어지면 손날로 오인식 | 정규화 없이 원본 좌표차로 외적 계산 → 손이 작아지면 값도 작아짐 | 단위벡터로 정규화 후 외적(사잇각의 sin) 사용 → **거리 무관** |
| 손등을 손바닥으로 판정 | front/back 부호가 반대 | 부호 뒤집음 |
| 손날 인식률 저조 | 임계값(8.6도)이 너무 엄격 | 16.3도로 완화 |
| 손날 유지 중 판정이 깜빡임 | 임계값 하나뿐이라 미세한 떨림에 경계를 넘나듦 | **히스테리시스** — 진입 0.28 / 이탈 0.42 |

> **반복된 교훈**: 고정 좌표값 기준은 카메라 거리에 취약하다. 항상 **그 대상 자체의
> 다른 부위(어깨 너비, 관절 간 거리)로 나눈 비율**로 판정해야 한다.

## 4. 커스텀 명령 슬롯

**요구**: 제스처에 사용자가 원하는 명령을 걸 수 있는 빈 슬롯이 필요하다.

**결정**: 이미 검증된 핀치 판정 방식을 손가락 조합만 바꿔 재사용 →
`pinch_middle`(엄지+중지) · `pinch_ring`(엄지+약지) · `pinch_pinky`(엄지+새끼) 3개.

### pinch_middle 오발동 — 로그로 원인 추적

"손을 올릴 때 자꾸 발동해서 크롬창이 10개 넘게 쌓인다"는 문제. 임계값을 추측으로
고치는 대신 **매 프레임 판정값을 파일로 남겨** 원인을 확인했다.

로그에서 확인한 것:
- 손이 `front → edge → back`으로 회전하는 동안 엄지-중지 거리가 **0.17 → 0.003** 으로 감소
- 실제로 붙인 게 아니라, **손을 옆/뒤로 돌리면 카메라 2D 투영에서 손가락이 겹쳐 보이는** 현상

**해결**: 클릭류 제스처를 **정면(front)일 때만** 판정. ON/OFF 이중 임계값과 최소
유지시간(0.1초)도 함께 추가.

## 5. 음성 인식

**요구**: 음성으로도 명령하고 싶다. 단, 주변에 사람이 많고 소음이 계속되는 환경이다.

**결정**: faster-whisper `medium` (GPU) — 소음 환경을 고려해 `small` 대신 선택.

**트리거 2개** (환경에 따라 골라 쓰도록)

| 트리거 | 녹음 종료 | 이유 |
|---|---|---|
| 손등 3초 유지 | 손을 뗄 때 (무전기 방식) | 손동작이므로 종료 시점을 직접 제어 가능. **소음 환경의 주력** |
| "웨이크" 발화 | 무음 1.2초 후 자동 | 손을 쓸 수 없을 때. 손동작이 없으니 자동 종료가 유일한 선택 |

> Whisper는 **"귀" 역할만** 한다 — 소리를 텍스트로 옮길 뿐, 의미 해석과 실행은
> 기존 `commandmodule`(LLM)이 그대로 담당한다. 즉 음성은 입력 경로만 추가된 것.

## 6. 모드 분리 (손동작 ↔ 전신 포즈)

**요구**: 박수로 손동작 인식과 전신 포즈 인식을 전환하고 싶다.

**동의한 이유** (요구보다 더 중요한 근거들)
1. **성능** — 두 인식기를 동시에 돌리면 FPS가 크게 떨어진다
2. **충돌 제거** — 전신 포즈는 필연적으로 손을 포함하므로, 동시에 돌리면 지금까지
   고생한 제스처 충돌이 훨씬 심해진다
3. **박수의 적합성** — 소리는 시각 제스처와 완전히 독립적이라 충돌 위험이 0이고,
   원래 박수가 맡던 예/아니오 역할은 이미 엄지척/다운이 가져가서 비어 있었다

### 명령 모듈은 복제하지 않고 공유

**요구**: 손동작용 명령 모듈 1개, 전신용 명령 모듈 1개.

**변경 제안 → 채택**: `commandmodule`은 "이름을 받아 등록된 명령을 실행"하는 범용
구조라 입력이 어디서 왔는지 신경 쓰지 않는다. 복제하면 LLM 프롬프트 · 화이트리스트 ·
`commands.json`을 두 벌 관리해야 한다. **모드별로 명령 세트를 분리하려는 목적은
등록되는 이름이 다르다는 것만으로 이미 충족된다** (`pinch_middle` vs `pose_*`).

### 되돌아오기 문제

포즈 모드에서는 mediapipe 손 추적이 꺼지므로 "양손 모임"을 판정할 수 없어 손 모드로
돌아올 수 없다. → **각 모드가 자기 검출기에서 손 위치를 가져오도록** 함:
손 모드는 mediapipe 손 중심점, 포즈 모드는 **포즈의 손목 좌표 ÷ 어깨 너비**.

### 박수 인식 문제 — 로그로 원인 추적

"박수가 인식이 안 된다"는 문제. 진단 로그를 보니 **박수는 이미 잘 잡히고 있었다.**
진짜 원인은 두 가지였다:

1. **타이밍** — `clap` 신호는 약 30ms만 유지되는데 카메라는 33ms에 한 프레임이라,
   두 신호가 같은 순간에 겹칠 확률이 낮았다
2. **박수 순간 양손 검출 실패** — 손바닥이 맞닿으면 mediapipe가 두 손을 하나로 봐서
   `hands_together` 자체가 깨진다

**해결**: "동시"가 아니라 **"박수 직전 1초 안에 양손이 모여 있었으면"** 인정.
(손날+스와이프에서 쓴 것과 같은 방식)

추가로 로그에서 **잡음과 박수를 가르는 건 고주파 비율이 아니라 음량(peak)** 이라는
것도 확인했다 — 키보드 클릭도 고주파 비율이 0.8까지 나온다.

**현재 상태**: 주변에 사람이 많아 박수 테스트가 어려워서, 당분간 **양손 모으기 1초
유지**만으로 전환하도록 해 뒀다. `MODE_SWITCH_REQUIRE_CLAP = True`로 되돌릴 수 있다.

## 7. 전신 포즈 인식

### YOLO-pose(17) vs MediaPipe Pose(33) → MediaPipe 선택

| | MediaPipe Pose | YOLO-pose |
|---|---|---|
| 설치 | **이미 있음** (손·얼굴에서 사용 중) | ultralytics + 모델 파일 필요 |
| 정규화 | `pose_world_landmarks` 제공 | 직접 계산 |
| 가려짐 | 랜드마크별 `visibility` 제공 | 키포인트별 conf |
| 다중 인원 | 1명 | 여러 명 |

다중 인원은 개인 비서에 불필요하고, 나머지는 모두 MediaPipe가 유리했다.

### 키포인트 구성

**요구**: 전신 명령이 아니라 **팔 동작 + 머리 동작**으로 명령하고 싶다.

| | 구성 |
|---|---|
| 처음 | 코 · 어깨 · 팔꿈치 · 손목 · **엉덩이** (9개) |
| 문제 | 책상 앞에 앉으면 엉덩이가 가려져 **계속 `pose skip`** |
| 최종 | 코 · **귀** · 어깨 · 팔꿈치 · 손목 (9개) |

엉덩이를 빼고 **귀**를 넣었다 — 머리 방향 판정에 필요하고, 웹캠 앞에서는 거의 항상
보이는 부위다. 또한 **필수(팔) / 선택(머리)** 을 나눠서, 머리가 안 보여도 팔 동작은
판정되도록 했다.

### 특징 벡터 (22차원)

좌표만으로는 "팔을 굽혔나 폈나"가 잘 구분되지 않아, **손 모듈에서 이미 검증된
관절 각도 방식**을 가져와 각도 특징을 추가했다.

```
정규화 좌표 9개 × 2 = 18   (어깨 중점 원점, 어깨 너비 스케일)
팔꿈치 각도 × 2       =  2   (0=굽힘, 1=폄)
머리 방향(돌리기/기울이기) = 2
```

### 박스 표시

MediaPipe는 YOLO와 달리 바운딩 박스를 주지 않으므로, **사용하는 관절들의 min/max로
직접 계산**해서 그린다. 박스 위 라벨은 분류기가 붙으면 `pose_name`이 그대로 표시된다.

## 8. 안정성

**문제**: 음성 명령 실행 중 Ollama 응답이 30초를 넘기자 **예외가 메인 루프까지
올라와 비서 전체가 종료**됐다.

**해결 3가지**
1. LLM 호출의 모든 예외를 잡아 **해당 명령만 실패**시킴 (비서는 계속 동작)
2. 음성 명령 실행을 **별도 스레드**로 분리 — LLM이 느려도 제스처 처리가 안 멈춤
3. Ollama 요청에 `keep_alive: "30m"` — 모델이 VRAM에서 내려갔다 올라오며 생기는
   수십 초 지연 방지

`commands.json` 읽기도 함께 감쌌다. 이 파일은 제스처가 인식될 때마다 실시간 루프에서
읽히므로, 파일이 깨져 있으면 같은 방식으로 전체가 멈출 수 있었다.

지금까지 **의도적으로 미룬 것**과 그 이유. 나중에 "왜 안 했지?" 싶을 때 참고.

| 항목 | 상태 | 이유 / 조건 |
|---|---|---|
| 자세 학습(분류) | 다음 작업 | 특징 추출(22차원)까지 끝남. 수집 → XGBoost/SVM/kNN 비교 → `pose_name` 연결 순서로 진행하기로 합의 |
| 눈 기능(블링크·모니터 끄기) | 맨 마지막 | EAR 개인차가 커서 한 기능에 매몰되었다고 판단, 손 기능을 먼저 강화하기로 함. 코드는 주석 처리 상태 |
| 박수 인식 튜닝 | 모드 전환에서 제외 | 주변에 사람이 많은 환경이라 박수로 전환하기 어려움. `MODE_SWITCH_REQUIRE_CLAP = False`. 인식 코드 자체는 유지 |
| 음성 명령 실사용 테스트 | 녹음 파일 대기 | 소음 환경이라 현장 테스트가 어려워 녹음 파일로 Whisper → LLM 경로를 검증하기로 함 |
| 웨이크워드 | 임시값 | "웨이크"로 두었으나 확정 아님 |
| `debug_pose.txt` 분석 | 로그 대기 | 사용자가 포즈 모드를 돌려 기록을 남기면 팔꿈치·머리 수치를 보고 임계값을 정하기로 함 (추측으로 정하지 않기 — 교훈 5) |
| UI 통합 | 보류 | 기능 검증이 먼저. 지금은 `main.py`와 `commandmodule.py`를 따로 실행 |

## 반복해서 나온 교훈

1. **고정 좌표값 기준은 거리에 취약하다** — 대상 자체의 다른 부위로 나눈 **비율**을 쓸 것
   (어깨 너비, 관절 간 거리, 단위벡터 외적)
2. **임계값 하나면 경계에서 깜빡인다** — 진입/이탈을 나눈 **히스테리시스**가 필요
3. **"동시"를 요구하면 거의 안 맞는다** — 신호마다 지속 시간과 주기가 달라서,
   **"최근 N초 안에"** 로 완화해야 실제로 동작한다
4. **순간 동작과 유지 동작을 구분하려면 최소 유지시간**을 둘 것
   (전환 자세가 스치듯 조건을 만족해서 오발동하는 걸 막음)
5. **임계값은 추측하지 말고 로그를 남겨서 실측할 것** — 두 번(pinch_middle, 박수)
   모두 추측한 원인과 실제 원인이 달랐다
6. **카메라 2D 투영의 한계를 염두에 둘 것** — 손·몸을 돌리면 실제로 떨어져 있어도
   화면에서는 겹쳐 보인다
